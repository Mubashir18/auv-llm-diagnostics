# LLM Diagnostic Agent for AUV Telemetry (HSE Project 2600)

Prototype of the diagnostic agent (Role B) for HSE Project 2600, *LLM solutions for anomaly diagnostics and recommendations in dynamic underwater AUV networks based on log analysis* (HSE MIEM, 2026–2027).

A rule-based monitoring step turns raw AUV telemetry into a short summary. A local LLM (Mistral 7B via Ollama), given reference documents through RAG, returns a structured JSON diagnosis with evidence and a recommendation.

> All data here is synthetic and generated by the scripts in `src/`. Results show that the pipeline works and where it is fragile, not how it will perform on simulator or real vehicle logs.

## Pipeline

```
synthetic telemetry (CSV)
      │
      ▼
monitor.py      window statistics → text summary + key numbers (JSON)
      │
      ▼
rag.py / diag.py  system rules + reference documents (ChromaDB) + summary
                  → Mistral 7B (Ollama, temperature 0, JSON mode)
      │
      ▼
{"anomaly", "confidence", "evidence", "recommendation"}
      │
      ▼
evaluate.py     accuracy, false positive rate, confusion matrix, baseline comparison
```

Fault classes: `none`, `propulsion_failure`, `navigation_drift`, `communication_anomaly`.

## Results

Held-out test set: 40 scenarios (10 per class), never used for tuning.

| System | Test accuracy | False positive rate |
|---|---:|---:|
| Hand-set threshold rule | 65% | 0% |
| Tuned threshold rule (tuned on dev set only) | **100%** | 0% |
| **LLM pipeline (Mistral 7B + RAG)** | **97.5%** (39/40) | 0% |

- 0 invalid JSON outputs on 92 runs.
- About 44 s per diagnosis on a laptop CPU (no GPU).

**Honest reading.** On this benchmark a well-tuned threshold rule is at least as accurate as the LLM. The LLM's possible value lies elsewhere: explanations, recommendations, and adding new fault types without labelled data and re-tuning. That is not measured yet.

## Key findings

1. **Summary wording drives the LLM.** Phrases like "packet loss rose from 5.3% to 5.3%" caused false alarms; fixing the monitoring rule cut the dev false positive rate from 60% to 0%.
2. **When text and numbers disagree, the LLM follows the text.** One missed navigation drift came from a summary that called a rising error "stable".
3. **Very late faults are invisible in a 10-second window.** All LLM errors were slow drifts that began 9–14 s before the log ended.
4. **RAG is not yet selective.** The same documents are retrieved for almost every summary, so RAG currently works as a fixed knowledge block.

## Setup

1. Install [Ollama](https://ollama.com) and run `ollama pull mistral`.
2. `python -m venv .venv`, activate it, then `pip install -r requirements.txt`.

## Run (from the repository root)

```bash
python src/gen_logs.py        # easy synthetic logs
python src/gen_hard.py        # dev set
python src/gen_test.py        # test set
python src/monitor.py         # logs → summaries
python src/rag.py             # reference documents → Chroma index
python src/evaluate.py --labels data/labels_test.csv --results data/results_test.jsonl --per-class 10
python src/tune_baseline.py   # threshold baseline
```
